# Recipient returns frontend

6 October 2026. Implements the V52 recipient-return contract, independently of financier returns.

- Outgoing payment entries expose a lazy Returned by recipient section when the source response supports returns. Source identity, recipient, recorded denomination and paid date are shown. Missing capability is unavailable, never zero returned money.
- The new commands retain exact six-decimal amounts, both revision tokens where required and source-bound ownership. Optional evidence selection reads the original payment's project, includes exact historical versions, and never inherits evidence during correction. ADMIN/FINANCE recording/evidence and ADMIN correction/void are driven by server row eligibility.
- Lost/uncertain command responses preserve the identical UUID/body in user/payment-scoped tab storage for deliberate retry. Definitive conflicts preserve form input, refresh observations and require review before adopting refreshed revisions. There are no automatic mutation retries.
- Gross commitments/payment comparisons are unchanged. All-row gross, returned-from-recipient and net-paid figures remain separate at payment/order level and in closeout observations. Null/mixed-currency scalar totals are unavailable; separate recorded-currency groups remain visible. Net paid does not authorise another payment or increase capacity.
- Original-payment correction/void uses refreshed server eligibility and its SOURCE_HAS_RECORDED_RETURNS diagnostics. No workaround invalidates genuine returns. Return corrections, voids, exact evidence and cross-page predecessor/successor entries remain readable.
- Parent payment-order history and Admin audit render RECIPIENT_RETURN context without affecting transaction/financier history. Success notices identify the correct return direction.
- Documentation requires the new recipientReturns section before printing. The report includes separate return totals/entries, captured currency, original payment/recipient identity, reasons, correction links and attribution. Its existing exact-document index shows recipient-return ownership and voided evidence separately from payment evidence and late attachments. Server report limits fail visibly. Successful commands notify open report tabs to reload the coherent report; manual refresh remains available.

Verification: 77 focused tests passed across recipient returns, outgoing payments, financier-return regressions, report, history, Admin, closeout and notifications.
